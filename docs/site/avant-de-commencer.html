Installer un agent, puis Kwa

Avant de commencer

Kwa ne remplace pas un agent de code : il l'encadre. Il vous faut donc d'abord un agent, Claude Code ou Codex, qui tourne sur votre machine. Si vous n'avez jamais utilisé d'agent, lisez d'abord le parcours 1 : il ne demande aucune installation.

  1. Ce qu'il vous faut

    • Python 3 : les garde-fous de Kwa sont de petits scripts Python, sans dépendance.
    • GitHub CLI (gh), connecté avec gh auth login : Kwa ouvre les issues et les pull requests avec. Les captures jointes aux issues passent par gh issue comment --attach (vérifié avec gh 2.102).
    • Node.js, seulement pour les serveurs MCP du parcours 2 (Context7, Playwright).
    • uv, seulement pour installer Graphify (parcours 2, étape 8).

  2. Installer un agent de code

    Claude Code

    Sous macOS, Linux ou WSL :

    $ curl -fsSL https://claude.ai/install.sh | bash

    Vérifier l'installation, puis lancer l'agent dans un projet :

    $ claude --version
    $ claude

    Compte : un abonnement Claude Pro, Max, Team ou Enterprise, ou un compte Console (facturation à l'usage). L'offre gratuite de claude.ai n'inclut pas Claude Code. Au premier lancement, la connexion se fait dans le navigateur.

    Windows, Homebrew, autres méthodes : documentation d'installation.

    Codex

    Sous macOS ou Linux :

    $ curl -fsSL https://chatgpt.com/codex/install.sh | sh

    Lancer l'agent dans un projet :

    $ codex

    Compte : au premier lancement, choisissez « Sign in with ChatGPT » ou une autre méthode de connexion proposée. Les offres qui incluent Codex sont listées par OpenAI.

    Windows, npm, Homebrew : documentation de Codex.

  3. Installer Kwa

    Kwa est un plugin : il s'installe une fois sur votre machine. Dans une session Claude Code :

    /plugin marketplace add nesyouyou/kwa
    /plugin install kwa@kwa

    Sous Codex :

    $ codex plugin marketplace add nesyouyou/kwa
    $ codex plugin add kwa@kwa

    Puis, dans une session ouverte dans votre projet :

    /kwa:init

    La skill montre ce que Kwa détecte, simule, puis prépare le dépôt après votre accord. Elle n'écrit que de la configuration (politique, bloc d'AGENTS.md, plugin proposé à l'équipe) : aucun script, aucun commit. Committez ces fichiers sur une branche et livrez-les par une PR : avec le module issue-flow, la PR doit porter « Closes #N », où N est le numéro d'une issue, à ouvrir d'abord (« Installer Kwa »).

    Sous Codex en ligne de commande, les hooks passent par la commande kwa, qui doit alors être dans le PATH : git clone https://github.com/nesyouyou/kwa ~/kwa, puis ajouter export PATH="$HOME/kwa/bin:$PATH" à ~/.zshrc. Validez ensuite les hooks du projet avec /hooks.

  4. Et ensuite

    Si vous débutez : le parcours 1 pour comprendre le modèle, la page Les briques pour voir à quoi ressemble chaque mécanisme, le parcours 2 pour le contexte, le premier pas en 30 minutes sur un projet d'exercice, puis le parcours 3 pour l'encadrer avec Kwa. Si vous travaillez déjà avec un agent : le premier pas, le parcours 3, puis Imposé ou suggéré et Quand alléger. Un mot vous échappe ? Le glossaire traduit chaque terme anglais.
