Kwa · Kit de Workflow Automatisé · v

Un kit de workflow automatisé pour le dev agentique

Un socle de process de développement pour travailler avec des agents de code : règles, garde-fous, skills, mémoire et workflow, les mêmes sur chaque projet. Ce qui change d'un projet à l'autre tient dans un fichier de politique.

Terminal
$ kwa install ./mon-projet --dry-run
  modules : core, craft, memory, issue-flow, verify, stack-prisma, stack-expo
  politique : créée à partir de la détection
  git : rien n'a été ajouté, commité ni poussé.
Pourquoi ce projet

Un support pédagogique, en français

Kwa montre, avec de vrais fichiers qui tournent, comment encadrer un agent de code. Il est fait pour apprendre et pour partager, avant d'être fait pour être installé.

Apprendre

Chaque pièce est lisible, testée et expliquée : règles, garde-fous, skills, mémoire. Trois parcours de formation vont de la culture de l'IA générative au harness.

En français

Presque tout ce qui existe sur le sujet est en anglais. Les skills, les règles et la documentation sont ici en français, pour celles et ceux que l'anglais freine.

Partager

Des bonnes pratiques issues de l'usage et d'idées reprises à d'autres projets, toujours créditées. Les retours et les corrections sont bienvenus.

Démarrer

Mémoire

Chaque session enrichit la suivante

D'autres projets captent des corrections ou des découvertes. Kwa y ajoute le journal des sessions, qui dit au démarrage où l'on en était, le refus d'un garde comme signal d'apprentissage, et le rangement dans la documentation partagée du projet. Rien n'est écrit sans votre accord.

1. CaptureSans y penser : vos corrections, vos « retiens : » et chaque refus de garde deviennent des candidats. Ou à la main : kwa-memory capture gotcha "…"
2. JournalEn fin de session substantielle, huit lignes : objectif, fait, décisions, reste à faire, pièges. Si vous fermez sans rien dire, un filet écrit au moins les faits.
3. FiltreSeulement le non-dérivable du code et de git. Chaque affirmation est revérifiée.
4. TriChaque apprentissage est routé vers la bonne destination, avec le diff exact.
5. RepriseAu démarrage suivant : la dernière session de la branche, l'état git et les notes en attente, en 2 000 caractères au plus.

Docs du projet

Décisions en ADR, pièges datés, conventions dans AGENTS.md. Versionné, lu par tout agent et tout collègue.

Garde-fous

Une erreur répétable devient une règle de la politique, avec son cas de test.

Mémoire de l'agent

Préférences de collaboration, retours sur la façon de faire.

Base de connaissance

Transverse aux projets : capture rapide dans la boîte de réception de l'équipe (KWA_VAULT_INBOX), jamais dans un fichier protégé.

Accord requisUn tableau de sept lignes maximum est présenté avec les diffs. Rien n'est appliqué sans « tout », « 1 et 3 » ou « rien ». « Rien à capitaliser » est une réponse valable.
Méthode

Ce que superpowers apportait, Kwa le porte

Le module craft reprend les principes de discipline (lois de fer, signaux d'alerte, revues en deux temps), réécrits en français et branchés sur la politique du projet. Un rappel de routage est injecté au démarrage de session, limité aux skills réellement installées.

Remplacer l'existant

Remplacer un outillage maison

Beaucoup de projets ont déjà leur propre jeu de scripts : hooks shell par projet, skills de déploiement, règles de dépôt. Kwa les porte dans le noyau (générique) et dans la politique (spécifique). kwa doctor signale les doublons à retirer, une fois la politique validée. Les cas d'un harnais de test réel sont rejoués contre Kwa avec examples/expo-monorepo.policy.json.

Limites et suite
Ce qui reste à faire

  

  
Les gardes ne sont pas une frontière de sécurité
Un agent peut en théorie éditer ses propres hooks ; guard-write demande confirmation avant de toucher à .claude/kwa/ et settings.json, rien de plus. Pour une vraie barrière : règles de protection de branche GitHub et permissions.deny.

  
Les gardes analysent du texte
Un script écrit dans un fichier puis exécuté, ou une commande assemblée à l'exécution, échappent à l'analyse. Les cibles calculées ($(…), variables) déclenchent une demande plutôt qu'un passage.

  
Feuille de route
1. Essai sur un projet pilote, toujours en simulation d'abord. 2. kwa sync : installer sur tous les projets listés dans un fichier de configuration. 3. Packaging en plugin Claude Code (skills seulement ; les hooks passent par l'installeur). 4. Évals de skills avec claude plugin eval, à vérifier sur la version en place. 5. Fusion guidée d'un CLAUDE.md existant dans AGENTS.md, avec contrôle de couverture. 6. Profil « projet client » : compte machine, politique de fusion humaine.

  
Ce que Kwa ne décide pas pour vous
Le contenu de la politique d'un projet (commandes interdites, environnements, pré-vols) vient de vos incidents. Kwa pré-remplit ce qu'il peut déduire et vous laisse le reste. Le module client-handover n'est jamais déduit : il dépend de l'intention.
