Des agents neufs, un prompt rempli

Skills qui délèguent

Trois skills ne font pas tout le travail elles-mêmes : elles le confient à des agents neufs. Un agent neuf ne voit pas la conversation. Tout ce qu'il sait, c'est le prompt que la skill lui écrit à partir d'un modèle rangé avec elle. La qualité du travail délégué dépend donc de ce prompt, et la skill garde toujours la vérification finale.

Ce que contient un prompt délégué

Ce qu'il doit savoir

La demande d'origine et ses critères de réussite, cités et non résumés ; les fichiers à lire ; les erreurs exactes collées ; ce qui est volontairement hors sujet.

Ce qu'il doit rendre

Un format de retour fixe : ce qui a été fait, les commandes lancées et leur résultat, les fichiers touchés, ce qui reste douteux. Court, pour ne pas remplir la fenêtre de la session.

Ce qu'il ne doit pas faire

Pas de commit ni de push, pas d'autre agent lancé, aucun garde-fou contourné : un refus se rapporte tel quel. Le relecteur, lui, ne peut rien écrire : c'est l'outil qui l'en empêche.

Ce que la session garde

La décision. Un rapport d'agent n'est pas une preuve : la session relance elle-même les vérifications du projet avant de dire « fait », et c'est vous qui validez.
